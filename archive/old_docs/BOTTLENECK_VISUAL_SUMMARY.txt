4. 计算图依赖结构（为何邻居数这么高？）
================================================================================

┌────────────────────────────────────────────────────────────────────────────┐
│                    PDE 时间步依赖传播示意                                    │
└────────────────────────────────────────────────────────────────────────────┘

时间步 t=0:
  V₀[1]  V₀[2]  V₀[3]  ...  V₀[19]
   │      │      │            │
   └──────┴──────┴────────────┘
          ↓ (Thomas算法耦合)

时间步 t=1:
  V₁[1]  V₁[2]  V₁[3]  ...  V₁[19]
   │      │      │            │
   └──────┴──────┴────────────┘
          ↓ (继续耦合)

时间步 t=2:
  V₂[1]  V₂[2]  V₂[3]  ...  V₂[19]
   ...

时间步 t=59:
  V₅₉[1]  V₅₉[2]  V₅₉[3]  ...  V₅₉[19]
    │       │       │               │
    └───────┴───────┴───────────────┘
                   ↓
              样条求解 M[1..19]
                   ↓
             最终插值 → price

依赖累积效果:
  - 早期节点: 依赖少数前驱   →  邻居 < 50
  - 中期节点: 依赖增加       →  邻居 ~100
  - 后期节点: 依赖大量前驱   →  邻居 ~200
  - 输出节点: 间接依赖全部   →  邻居 300+

================================================================================
最终结论
================================================================================

PDE + Edge-Pushing 不是最优组合！

原因:
  - PDE时间步全局耦合 → 高扇出 (196 neighbors/node)
  - 与论文中的局部代数函数不同 (13 neighbors)
  - Edge-Pushing复杂度 O(n × neighbors²) 在这里爆炸

推荐:
  生产环境: 使用 Bumping (2.6秒，精度高)
  研究用途: Jacobian + Bumping (结合AAD和数值)
  未来优化: 实现 Double AAD (3 PDE solves理论)

Edge-Pushing在PDE中的教训:
  ✓ 算法本身没问题 (W矩阵99.95%稀疏)
  ✓ 实现也没问题 (邻居查找O(degree))
  ❌ 但应用场景不匹配 (迭代算法 vs 代数函数)
